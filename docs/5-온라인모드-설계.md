# 온라인 모드 설계 (구현 완료)

## 상태

- ✅ **구현 완료**: 방 생성(O) / 코드 조인(?join=) / 게스트 입력 릴레이 /
  20Hz 스냅샷 미러링 / UI·사운드·카메라 오퍼레이션 중계 / WebRTC 보이스챗(V).
- 해커톤 제출 기본은 여전히 **로컬 동일화면** (심사자가 링크만 눌러 평가,
  서버 의존성 0). 온라인은 릴레이 서버를 배포한 경우에만 활성화된다.
- 물리 롤백 넷코드는 Rapier 스냅샷 비용·복잡도 대비 파티 게임 가치가 낮아 배제.

## 알려진 제한 (v1)

- 돌풍 스트릭 파티클은 게스트에게 미표시 (방향 화살표 배너는 중계됨)
- 생성형 GLB 에셋은 게스트에서 절차적 비주얼로 표시 (추후 게스트 로더 연결)
- 게스트 중도 이탈 시 해당 플레이어는 자리에 멈춤 (다음 판까지 유지)
- 보이스챗은 STUN만 사용 — 일부 엄격한 NAT 조합에서는 연결 실패 가능(TURN 미구성)

## 아키텍처

```
게스트 브라우저 ──입력(InputState, 60Hz)──▶ 릴레이 서버 ──▶ 호스트 브라우저
                                                        (물리·게임 로직 실행)
게스트 브라우저 ◀──상태 스냅샷(20Hz)+이벤트── 릴레이 서버 ◀──
```

- **호스트 = 서버**: 방을 만든 브라우저가 현 게임 코드를 그대로 실행. 물리는 호스트에만 존재.
- **게스트 = 씬 뷰어**: 스냅샷(플레이어/프롭 위치·회전, HUD 상태)을 받아 렌더만 한다.
  물리 월드 없이 Three.js 씬만 구동 + 보간(interpolation) 100ms 버퍼.
- **입력 추상화는 이미 완료**: 게임 로직은 `InputSource.getState()`만 본다.
  게스트 입력을 `RemoteInputSource`로 감싸면 호스트 게임 루프가 그대로 소비한다.

## 구현 단계

1. `NetChannel` (WebSocket 래퍼: create/join/input/state/ev) — 프로토콜은 relay.mjs 참고
2. `RemoteInputSource implements InputSource` — 게스트 입력 버퍼 (호스트 측)
3. `SnapshotEncoder` — Float32Array 패킹 (플레이어 4×[pos,yaw,held] + 프롭 34×[pos,quat])
   ≈ 34×7×4B ≈ 1KB/스냅샷 × 20Hz = 20KB/s — 충분히 가볍다
4. 게스트 렌더 전용 모드 (`Game`에서 physics step 스킵 + 스냅샷 적용)
5. 사운드·UI 이벤트 릴레이 (`ev` 메시지: 그랩/명중/심사 결과)
6. 메뉴에 "방 만들기 / 코드 입장" UI

## 서버 배포 후보

| 후보 | 비용 | 비고 |
|---|---|---|
| Render.com Web Service | 무료 티어 | ws 그대로 실행, 슬립 있음 |
| Fly.io | 무료 크레딧 | 저지연, 슬립 없음 설정 가능 |
| Cloudflare Durable Objects | 유료($5/월~) | 글로벌 엣지, relay.mjs 포팅 필요 |

## 리스크

- 호스트 이탈 = 방 종료 (파티 게임 관례상 수용)
- 호스트 핑 우위(호스트가 유리) — 캐주얼 파티 게임이므로 수용
- 스팀 출시 시엔 Steam Relay(SDR) + Steamworks 로비로 대체 검토
