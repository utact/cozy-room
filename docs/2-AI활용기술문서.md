## 2. 개발 프로세스에서의 AI 활용 (Claude Code)

게임의 기획 문서(DESIGN.md), 전체 소스 코드, 자동 검증 스크립트를 Claude Code와의
대화형 개발로 제작했다. 전 과정이 GitHub 커밋 기록에 남아 있다.

**주요 지시 사항(프롬프트) 예시:**
- "2~4인이 흐느적거리는 캐릭터로 물건을 뺏고 던지는 파티 게임. 화면 중앙에 주제가
  뜨고, 시간 경과 후 AI가 한 줄 평과 함께 우승자를 선정" — 초기 컨셉 전달
- 물리 엔진 비교 검토(Rapier/cannon-es/Jolt) 후 선정, 마일스톤(M1~M4) 역산 계획
- 회색 상자 → 콘텐츠 → 비주얼 → 문서의 단계별 구현 및 Playwright 헤드리스
  스모크 테스트로 매 단계 실플레이 검증

## 3. 런타임 AI 심사위원 구조

```
버저 순간 → JudgePayload { 주제, 플레이어별 제출물(이름+태그) }
         → Judge 인터페이스
            ├─ LocalJudge  : 태그 가중치 매칭 + 템플릿 문장 풀 (오프라인, 기본값)
            └─ RemoteJudge : LLM 프록시 호출 (?judge=URL, 실패 시 Local 폴백)
         → JudgeResult { 플레이어별 점수(0~100) + 한 줄 평 }
```

- **LocalJudge**: 프롭 카탈로그의 28종 아이템에 부여된 태그(무기/귀여움/생존…)와
  주제별 태그 가중치를 매칭해 채점하고, 점수 구간별 템플릿 문장 풀(±변덕 점수,
  태그 추임새, 중복 방지)로 한 줄 평을 생성. 정적 웹 빌드에서 API 키 없이 항상 작동.
- **RemoteJudge**: 실제 LLM(Claude) 심사용 훅. 서버리스 프록시에 아래 형식으로
  POST하며, 6초 타임아웃/오류 시 LocalJudge로 자동 폴백.

**LLM 심사 프록시용 프롬프트(예시):**

```
당신은 파티 게임의 유쾌한 심사위원이다. 주제: "{topic}"
각 플레이어가 제출한 물건(이름/태그)을 보고 주제 적합도를 0~100점으로 채점하고,
한국어로 위트 있는 한 줄 평을 작성하라. 빈손 제출자는 낮은 점수와 함께 놀려라.
JSON으로만 답하라: {"verdicts":[{"playerId":0,"score":85,"comment":"..."}]}
```

## 4. 생성형 3D 에셋 파이프라인

```
생성형 3D 도구(GLB) → public/assets/props/{id}.glb + manifest.json
→ 게임이 자동 로드 (카탈로그 스케일 정규화) → 실패/부재 시 절차적 비주얼 폴백
```

물리 콜라이더·심사용 태그는 코드의 카탈로그 메타데이터가 담당하므로,
에셋은 비주얼만 교체된다.

- 사용 도구: `[ 예: Meshy AI — 생성 모델명/버전, 라이선스 확인 결과 ]`
- 생성 프롬프트 예시: `[ "low-poly cute frying pan, game asset" 등 실제 사용 프롬프트 ]`
